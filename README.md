# KNOSSOS [![Build Status](https://ci.appveyor.com/api/projects/status/qehrybs5vpvjou28?svg=true&pendingText=building&passingText=OK&failingText=not%20OK)](https://ci.appveyor.com/project/knossos/knossos)

## Background
KNOSSOS is a software tool for the visualization and annotation of 3D image data and was developed for the rapid reconstruction of neural morphology and connectivity.

## Technical
By dynamically loading only data from the surround of the current view point, seamless navigation is not limited to datasets that fit into the available RAM but works with much larger dataset stored in a special format on disk. Currently, KNOSSOS is limited to 8-bit data. In addition to viewing and navigating, KNOSSOS allows efficient manual neurite annotation ('skeletonization').

## Use
KNOSSOS is being used mostly for reconstructing cell morphologies from 3D electron microscopic data generated by Serial Block-Face Electron Microscopy (SBEM), with an occasional application to 2-photon and confocal optical microscopy data.

## Changes in this fork

This fork ([atc3/knossos](https://github.com/atc3/knossos)) extends [KNOSSOS](https://github.com/knossos-project/knossos) for refining 3D EM segmentations: correcting and completing existing labels across large datasets, without a separate tool. Everything below is in `master`. **Help ▸ Cheatsheet** lists every shortcut for the current mode.

### Shape interpolation
A new **Segmentation Shape Interpolation** mode, natively and on the scale of whole datasets — Paintera's workflow without loading the whole segmentation into memory.
- Paint an object on a few spaced-out slices and everything between them is interpolated (signed distance fields, physical voxel spacing so anisotropic data interpolates correctly) and previewed live; **Enter** writes the whole chain. Key slices show amber, interpolated ones cyan.
- The axis follows the viewport you start in; the other two viewports show a cross-section through the chain.
- Adopt an existing label as a key slice by clicking it (left replaces, right adds a piece), with the whole outline picked up across blocks, not just what is on screen. Paint or erase on an interpolated slice to correct only the part you touch.
- **← / →** jump between key slices, **Delete** removes one, **Ctrl+Shift+C / V** copies a slice's outline onto another, **Esc** ends the chain, **S** toggles with paint mode.
- Optional centroid alignment, so a structure drifting sideways does not pinch.
- Writes only the blocks the shape reaches, and works above magnification 1.

### Painting and filling
- **Flood fills** that respect what is loaded: **G** / **Shift+G** fill in 2D / 3D under the mouse pointer. A fill stops at the edge of the loaded blocks instead of silently writing into unloaded ones; 2D fills can optionally load more blocks and continue. A fill still running after 2 s (usually one started in the background by mistake) pauses and asks whether to keep filling, keep what it has filled, or undo it.
- **Fill enclosed areas (H):** close an outline and its inside joins the object when you release.
- **Paint the background (0):** select background as the paint id, so the brush and fills erase.
- **Overwrite control** (toolbar): paint over anything, only unlabelled voxels, or only unlabelled voxels not touching another label, which keeps a one-voxel gap around each object.
- A **paint-id field** in the toolbar; brush strokes are continuous between mouse samples; the brush size is remembered across launches.
- **Lock painting to a magnification** (Action menu).

### Undo
- **Undo / redo for segmentation edits** (Ctrl+Z / Ctrl+Shift+Z) with a **History** window. Each stroke, fill, interpolation or morphology run is one step; edits to blocks that have since been evicted still undo.
- **Merges are undoable** — in Segmentation Merge mode, from the Segmentation tab's Merge, and in Merge Tracing mode (where undo removes the node that caused the merge).

### Object inventory
An **Inventory** tab in the annotation window lists every object in the segmentation layer with a position, so existing annotations can be found rather than hunted for.
- Built by a slow background scan at a coarse magnification, on its own thread, yielding to normal block loading. Progress and an ETA show in the tab and the status bar. Scans are cached on disk and resume where they stopped.
- **. / ,** jump to the next / previous object from any mode. The list is in scan order and only ever grows, so repeated presses walk it once. Filter by size, hide objects already annotated or visited.
- **Route** column: sort by it to walk the list loading as few blocks as possible — nearest-first, or a sweep along a Hilbert curve when the dataset is bigger than the memory cache, whichever is cheaper. While you look at one object the next two are downloaded in the background. **Re-route** plans it again over the objects shown now, from where you are — after narrowing the filter, or with “hide visited” on to pick up where you left off.
- **ID range** filter: the two boxes after “hide visited” show only ids from A to B, inclusive; leave one empty for no bound on that side.
- Tracks per object whether it has been visited, painted, erased or has a skeleton; this state is saved in the `.k.zip`.
- **Erase** an object entirely: the Erase button, **Ctrl/Cmd+Backspace** from anywhere, or **Delete / Backspace** while the list has focus. Confirmed first, one undo step.
- Works for KNOSSOS cube datasets and for Neuroglancer precomputed volumes.

### Dilate, erode, smooth
- **Action ▸ Dilate Object / Erode Object** grow or shrink the selected object; **Dilate, Erode, Smooth…** holds the settings and Paintera-style smoothing (Gaussian of the object's mask, thresholded; direction In / Out / Both).
- The radius is a physical distance, so on anisotropic data it reaches further in-plane than through sections; the panel shows the reach per axis.
- Fragments of a merged object grow as themselves. Works over a region about the crosshair. Ported from Paintera's algorithm.

### Datasets and loading
- **Neuroglancer precomputed segmentations** (`ServerFormat = 'precomputed'` in a `.k.toml`): sharded and unsharded, `compressed_segmentation` and raw, uint64. Volumes the reader cannot handle yet (other data types, gzip shards, a non-zero `voxel_offset`) are refused with the reason rather than shown wrong.
- **Google Cloud Storage** datasets load (they were mistaken for Brainmaps volumes, and sent auth requests GCS does not answer).
- **File ▸ Open Annotation From URL** downloads a `.k.zip` or `.nml` (https:// or gs://) into `annotationFiles/downloaded/` and opens it; dragging such a link onto the window does the same.
- Downloaded blocks are kept in memory after you move away (1 GiB by default; set in the dataset dialog), so going back does not download them again.
- **File ▸ Reload Dataset From Server** re-fetches blocks when files changed on the server, bypassing Google's edge cache for an hour. Blocks you painted keep your edits.
- A `.k.toml` layer can declare `MaxId`, so new objects get ids above those already in the data.
- An unreadable `ServerFormat` is reported instead of the layer silently loading empty.
- Selecting a dataset in the dataset dialog no longer stalls on auth requests; pasted paths and URLs have surrounding whitespace trimmed.

### Interface
- **Viewport layouts:** stock arrangements plus your own named presets.
- **Number keys 1–9** switch annotation mode, in the order of the mode list.
- Default annotation file names start with the dataset name (`<dataset>_annotation-<date>.000.k.zip`).
- **File ▸ Go To Annotations Folder**, and an **Action ▸ Memory Report**.

### Fixes
Crashes and freezes fixed include: dangling pointers into caches that evict under their readers; a large interpolation's preview freezing the application; the Layers panel crashing on a precomputed layer; inventory scans that hung, double-counted blocks on resume, or hid objects that grew past the size filter. Many smaller fixes to fills, undo and the interpolation chain are described in the commit history.

### Building on macOS
Local builds are signed automatically if a signing certificate exists, so macOS keeps folder permissions across rebuilds. Create one once with `ci/macos_make_signing_cert.sh`; without it the build is unchanged.

### Tests
Standalone tests for the numerical and geometric code — distance transforms, interpolation slicing and block planning, hole filling, morphology, the inventory, the precomputed format — are in `tests/`; see `tests/README.md` for how to build and run them.
